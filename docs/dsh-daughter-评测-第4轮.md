## 2. 我用新识别器复算了真实语料，结论要改

上一轮我写"56 条真实语料负向 0 条，已经不是数据不够，是识别器看不见负面"。这轮把新识别器拉出来跑了两组对照：

**（1）典型负向句，10 条**

```
 -0.588   今天好累，撑不住了
 -1.000   我怕又失败了
 -0.600   不开心
 -1.000   感觉没意思，算了
 -1.000   有点焦虑，担心做不完
  1.000   开心，谢谢你
  1.000   这个功能不错，挺满意的
 -1.000   我有点失望
  0.000   别管我了
 -1.000   睡不好，心累
```

9/10 正确。唯一漏的「别管我了」是纯否定祈使句——没有正面词可被否定，"别"单独不产生负分。这属于可接受边界，记一笔即可。

**（2）用新识别器复算库里 34 条真实 chat 事件**

- 会翻成负向的：**只有 1 条**（"我怕又失败了" → −1.0）
- 其余 33 条仍是微正（0.05–0.23）

所以正确归因是：**识别器确实有缺陷（已修好），但真实语料的 0 负向，更大原因是"这段对话里几乎没有人表达情绪"** ——当前语料是"更新了记忆插件，现在试试""又优化了一点"这类开发对话。

这个区别很关键：如果按上一轮的结论继续扩词表，收益接近 0（词表已经覆盖了"累/烦/怕/撑不住"这些最典型的）。真正该做的是下一条。

**（3）新发现：极性饱和**

10 条样例里有 **6 条打到 ±1.000**。原因是 `polarity = (pos − neg) / max(1, pos + neg)`——只要一侧为 0，结果必然是 ∓1，与"有点烦"和"崩溃"无法区分。幅度目前靠 `strength = hits/2` 缩放，但 `strength` 也是粗粒度计数，不是程度。

后果：`emotion_match = 1 − PAD距离` 仍会是**分段常数**（微正 / 满负 两档），上一轮说它"形同虚设"的判断在修好识别器之后依然成立，只是从"全正"变成"两档"。

## 5. 下一步（只剩三件，都与"情感臂真正生效"有关）

1. **把 polarity 从"符号"改成"分级"**。当前 `±1` 饱和是情感臂最后的机制性缺陷。做法：按命中数与程度词（有点/挺/特别/太/非常）分 3–4 档，输出 −1..1 的连续值；`strength` 保留但改由档位驱动。验收：同一批样例不再有 6 条打满 ±1，且"有点烦"≈−0.2、"崩溃"≈−0.9。
2. **让极性分布可观测**。加 `logs/polarity/<角色>.jsonl`（每轮 polarity / strength / 命中词），两周后统计分布。当前所有关于"负面不够"的判断都只能靠离线复算，缺一份时间序列。
3. **补两处文档一致性**：R-08 改成"已扩表（19/30）+ 否定处理，仍缺程度与对象"；P9 统一为 4/7（design 两处 + README）。
