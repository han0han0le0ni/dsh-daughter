## 6. 优化路径（7 条，按性价比排序）

### 路径 1｜把数字变成生成物，而不是手写（根治时效性）

新增 `scripts/docs-sync.ts`，从代码反推文档中的可变事实：`npm test` 项数、测试文件数、`src` 模块清单、`config.yaml` 的 key 集合、P9 已接通连接器、当前库事件/技能/重构统计。三个动作：

- 文档里所有会漂的数字改成占位符（`{{tests}}` / `{{p9}}` / `{{modules}}`），`docs-sync` 渲染；
- `check:link` 增加第 19 项 `docs-freshness`：占位符渲染值与实测不一致就 FAIL；
- 顺手删掉工作区 `docs/` 副本，改为指向插件仓库，避免再出现"三层滞后"。

验收：把 `npm test` 改成任意数字，`check:link` 立刻 FAIL。这一条做完，本次报告里 A 类差异（7 处）永久不会复发。

### 路径 2｜给设计文档补三个骨架章节，而不是三篇轮次记录

- §3 架构图加"动机决策层（选谁做）/ 自主开口回路（要不要主动说）/ 表达出口层（投给谁）"，并明确**后两者不属于单轮**；
- §6.3 单轮顺序补 `motivation → decide`、`retrieve(min_semantic) → association(fallback)`；新增 §6.4「异步环路」描述 speak timer → expression sink；
- §7 流程图加"无人说话 → speak tick → hold/act"分支；
- §4 补 `MotivationBreakdown` / `SpeakPlan` / `ExpressionSinkConfig` 的类型定义；
- §11 配置块改为**从 `config.yaml` 生成**（配合路径 1），彻底消灭"配了但文档没有"。

同时重写 §1.3 非目标：**不合成语音、不渲染形象、不做皮肤动效，但拥有"这段话投给哪个前端"的投递决策权**。

### 路径 3｜抖音噪声治理（当前最实的技术债）

20/38 条同质事件、`pleasure` 恒 0.098、召回 0 次，这是当年"前台切换淹没记忆"的翻版。三条改法可叠加：

- **签名归一化扩到被动消费来源**：去掉作者名、集数、日期、`@` 前后缀后做签名，让同模板进同一桶；
- **给来源加日配额与占比上限**：`douyin_content` ≤ 5 条/天、总活跃占比 ≤ 20%，超出直接 drop 只计数；
- **显著性降权**：被动消费无互动信号，`source_weights.douyin_content` 0.85 → 0.6，或引入"用户未提及则不计社交性"。

验收口径：连跑 3 天后 `douyin_content` 占比 < 20%、同模板事件数 ≤ 3、检索命中里出现 `chat` 来源的比例上升。

### 路径 4｜把"回忆重构 0 行"当 P0 缺陷处理，不要再等数据

38 条真实事件 + 18 轮仍为 0，说明绝对阈值路线走不通（`padDistance` 满量程 1.0，0.08 对应单维 pleasure 变化约 0.5）。改成事件驱动：

- 触发条件从"距离 > 阈值"改为"本轮 `|Δpleasure| ≥ 0.15` 且事件为累积级以上"，与人格冲击共用 `scoreImpact` 的分级结果；
- 记录"回看触发率"，目标 5%–15%（可按周统计）；
- `check:link` 加一条断言：模拟 20 轮正负交替对话后 `emotion_history > 0`。

这条不修，整套"记忆会被现在改写"的设计在真实数据上等于没有实现。

### 路径 5｜情绪识别从"补词表"升级为"三步走"

22 词表 + 命中数差已被真实数据证伪（负值 0 条）。建议顺序，不要跳步：

1. **规则层**：否定（不/没/别）、程度（有点/挺/特别/太）、转折（但是/不过/虽然）三类前缀处理，预计半天，能把"不太想说话""有点累"识别成负向；
2. **标定集**：人工标 100 条真实语句做 baseline，算 precision/recall，再看 `emotion_match` 的方差是否 > 0.02；
3. **必要时才上模型打标**（一次轻量调用），并用 1 的结果做对照。

验收：真实语料负值占比 > 15%、`|pleasure|` 方差 > 0.02、`emotion_match` 不再是常数。

### 路径 6｜动机层与主动开口跑"影子模式"再定阈值

两个新层目前只有单测，没有真实分布。加 `speak.shadow` 与 `motivation.shadow`：

- `shadow=true` 时只写决策结果（urge/threshold/score/breakdown）到 `logs/`，不投递、不执行；
- 跑两周后拿 `urge` 与 `threshold` 的分布定 `threshold 0.62`、`max_per_day 5`、`hold_ratio 0.75` 是否合理；
- 同时验证 `Math.random()` jitter 是否真的需要——若 `seed` 派生 rng 也能产生足够不规律感，直接改掉（顺带修矛盾 1）。

验收：拿到 ≥ 500 次决策样本，`act` 率落在 8%–15%。

### 路径 7｜把运维脚本纳入自检，补上覆盖缺口

`reset` / `memory-doctor` 已有 7+5 项单测，但 18 项自检（`check:link`）一项都没覆盖，而它们恰恰是**会动真实数据**的操作。建议加三条：

- `reset --dry-run` 在临时库上不改变任何计数；
- `memory-doctor` 能检出人为制造的三类不一致（孤儿全文、悬空边、FTS 探针失败）；
- `reset --apply` 后读回复核失败时退出码非 0（当前只在真实数据上验证过）。

顺带把 `check:link` 从 18 项扩到 22–24 项，覆盖动机/开口/出口/抖音四个新模块的"能不能通"。
