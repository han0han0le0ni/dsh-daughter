## 3. 本轮新发现（都有实测证据）

### 3.1 【高】演化日志 ID 撞号，可追溯性受损

`logs/evolution` 共 8 条，**只有 5 个唯一 ID**：

```
EVO-20261106-99e1  × 3
EVO-20261106-da3a  × 2
```

根因在 `store.ts:849`：后缀取 `Math.floor(this.rand() * 0xffff)`，而 `rand = createRng(config.seed)` 是**同一 seed 的确定性序列**。Store 一旦重建（插件重载 / 进程重启 / 多实例），随机流从头开始，于是后缀按同样的次序重放，撞上前一天写过的号。

影响：G5「每次变更可追溯」依赖日志条目可唯一定位；ID 重复会让面板按 ID 展开、星图"最近演化"跳转、外部审计去重全部指错条目。这不是理论风险，**当前库里已经发生**。

修法（半小时）：后缀改 `已存在检查 + 自增`，或拼 `util.ts` 里已有的 `PROCESS_NONCE`，并补一条"连续写 100 条日志，唯一 ID 数 = 100"的测试。

### 3.2 【高】`participants` 恒为 `["self","user"]`，抖音被记成"我俩的共同经历"

55 条事件**全部**是 `["self","user"]`，包括 23 条 `douyin_content`。根因是 `memory.ts:298` 统一写 `['self', ctx.audience ?? 'user']`，外部内容源也走这条路径。

三个连锁后果：

1. **显著性虚高**：`filter.ts:106` 用 `participants.includes('user')` 判社交性 → 抖音事件的 `social` 恒为 1，这也是它显著性能到 0.35 的原因；
2. **人物画像被污染**：星图人物节点、关系网、亲密度按"参与事件"累加，刷视频被算成和用户的互动；
3. **L2 关系锚点失真**：`user.intimacy` 由参与事件权重累加，55 条里 23 条是抖音 → 目标值被抬高，关系深度成了"刷了多少视频"的函数。

修法：外部来源只记 `['self']`（或 `['self', 'douyin:作者']`），社交性改按来源判定；补一条"douyin 事件 participants 不含 user"的回归用例。**这是本轮最值得先修的一条**，一处改动同时修三个下游。

### 3.3 【中】重构记录是批量爆发式的，缺节流

24 条记录来自 20 个事件，全部集中在 22:43:27 与 22:45:55 两个时间点，**同一时间戳一次写 3 条**（`EVT-...05d52f / 13a3a7 / 2ba3a1` 时间完全相同、`pleasure` 都是 0.06）。

原因是 `reconstructOnRecall` 对本轮每条 recall 逐一判定，没有"同一事件冷却"和"每日上限"。阈值 0.08 前，它一条都不写；阈值一达标，就成批写。按当前节奏，聊一天能写几十条，`emotionNowHistory`（上限 8 条、超出合并）会被快速填满，把"回看感受"的语义稀释成"每次召回都记一笔"。

建议：每事件 24h 内最多 1 条 + 每会话每日上限（如 5 条），并让 `reason` 带上位移量（`Δ=0.11`），否则面板看不出"为什么算重构"。

### 3.4 【中】关系阶段 32 轮后仍停在 `stranger`

`l2_relationship.yaml`：`relationshipStage: stranger`、`relationshipDepth: 0.093`、`trust: 0.369`，而 `personaTurns = 32`。

原因不是锚点错（上轮已改锚），而是**频率与步长**：`evolvePersona` 每天最多一次，步长 `0.04 + 0.08×质量`，而 `acquaintance` 阈值是 0.15。8 条演化日志里 L2 只写过一次（`lastPersonaEvolveAt` 还是 05:14Z）。也就是说：**一天里聊 32 轮，关系只走近 0.04；要到"初识"得连着用 2–3 天。**

这未必是 bug（"关系本来就该慢"），但和"依恋焦虑 0.826 的黏人角色"放在一起是矛盾的：她焦虑，但关系不动。建议要么把 `evolvePersona` 改成"跨天 + 每 N 轮"双触发，要么让步长随当日互动质量累积，并在面板标出"距下一阶段还差多少"。

### 3.5 【低】人格出生值越界

`l1_baseline.yaml`：`openness 0.86`、`conscientiousness 0.82`，均**超出** `config.yaml` 声明的出生区间（[0.45,0.75] / [0.4,0.7]），且 `innate` 同为 0.86/0.82。说明这个角色不是走 `createInitialL1` 抽样出来的（来自 reset 的自定义值，或旧存档兜底路径），**区间约束没有覆盖非抽样入口**。另外 `plasticity 0.65 > plasticityBase 0.35`，与"可塑性随经历衰减"的表述方向相反，语义待确认。

### 3.6 【低】仍在两处违背"可复现"

`host.ts:893` 的 speak jitter 仍用 `Math.random()`；设计 §6.1 明写"`src` 中不再出现"。改成 `createRng(seed)` 派生即可，顺带让主动开口的时间线在测试里可复现。
